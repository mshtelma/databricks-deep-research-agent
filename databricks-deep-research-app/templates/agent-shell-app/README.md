## Deploy

```bash
# 1. Extract the zip.
unzip {{ app_name }}.zip -d {{ app_name }} && cd {{ app_name }}

# 2. (Optional) edit databricks.yml — uncomment + customize the
#    serving_endpoint resource block to point at your Mode 3 deployment
#    (or any pre-bound endpoint such as databricks-claude-sonnet-4-5).
#    Then set MLFLOW_EXPERIMENT_ID by editing the experiment_id under
#    resources.apps.{{ app_name }}.resources.

# 3. Deploy.
databricks bundle deploy --target dev
databricks bundle run {{ app_name }} --target dev
```

## MLflow tracking

This shell app writes MLflow traces to the **workspace default experiment** —
no `MLFLOW_EXPERIMENT_ID` resource binding is required.  On first trace write
MLflow auto-creates the experiment under `/Shared/` if it does not already
exist.

If you need per-app experiment isolation, create an MLflow experiment in the
Databricks UI, then add the following block to the
`resources.apps.{{ app_name }}.resources` section of `databricks.yml` and
re-deploy:

```yaml
- name: 'experiment'
  experiment:
    experiment_id: '<your-experiment-id>'
    permission: 'CAN_EDIT'
```

You will also need to add a corresponding env entry to `app.yaml`:

```yaml
- name: MLFLOW_EXPERIMENT_ID
  valueFrom: 'experiment'
```

## Framework version

The framework version shipped with this zip is encoded in the wheel filename:
`{{ framework_wheel_filename }}`. To upgrade to a newer framework, re-export
the shell app from the Designer after the parent DRE app has been redeployed
with a newer framework wheel built by `make build-framework`.
